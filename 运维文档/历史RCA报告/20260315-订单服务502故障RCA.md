# 20260315 订单服务 502 故障 RCA

## 1. 事件摘要

| 项目 | 内容 |
|------|------|
| 时间 | 2026-03-15 14:02–14:47（45 分钟） |
| 影响 | 订单创建失败约 12%，约 3.2 万笔受影响 |
| 根因 | 发布后 order-service 连接池配置错误，upstream 连接被拒绝 |
| 触发 | 灰度 20% 流量时暴露 |

## 2. 时间线

| 时间 | 事件 |
|------|------|
| 14:02 | 监控告警：网关 502 率 > 5% |
| 14:08 | On-call 确认 order-service 新版本 Pod CrashLoopBackOff |
| 14:15 | 回滚至 v2.2.8，502 下降但未完全恢复 |
| 14:28 | 发现 env `DB_POOL_SIZE=0` 配置笔误 |
| 14:35 | 热修 ConfigMap 并滚动重启 |
| 14:47 | 指标恢复正常，解除公告 |

## 3. 根因分析

- CI 模板合并冲突导致 `DB_POOL_SIZE` 被覆盖为 0
- 预发环境未覆盖该配置路径，灰度前检查清单未包含连接池项
- 回滚后旧版本 Pod 仍读取错误 ConfigMap（共享配置）

## 4. 改进项

| 项 | 负责人 | 截止 |
|----|--------|------|
| ConfigMap 变更双人复核 | SRE | 已完成 |
| 发布前自动校验关键 env 非零 | 平台组 | 2026-04-01 |
| 灰度观察窗延长至 30 分钟 | 订单域 | 已完成 |

## 5. 经验教训

配置类故障应优先检查共享 ConfigMap 与 Secret，而非仅关注镜像版本。
