# 微服务依赖关系

## 1. 核心链路（下单）

```
order-service
  ├── user-service（鉴权、地址）
  ├── product-service（库存、价格）
  ├── payment-service（支付）
  ├── inventory-service（扣库存）
  └── notification-service（消息通知）
```

## 2. 同步 vs 异步

| 调用 | 类型 | 中间件 | 超时 |
|------|------|--------|------|
| order → payment | 同步 HTTP | - | 3s |
| order → inventory | 同步 gRPC | - | 2s |
| order → notification | 异步 | Kafka topic `order.events` | - |

## 3. 强依赖与弱依赖

| 服务 | 强依赖（不可用则核心失败） | 弱依赖（可降级） |
|------|---------------------------|------------------|
| order-service | user, product, inventory | notification, 推荐 |
| payment-service | 支付渠道、账务库 | 营销券 |

## 4. 雪崩防护

- 网关层熔断：错误率 > 50% 10s 则 open 30s
- 关键下游配置 bulkhead 线程池隔离
- 弱依赖失败不阻塞主流程（异步补偿）

## 5. 变更影响评估

修改 `product-service` 接口时，需通知：order、cart、search 三个消费方。
变更评审模板见内网「API 变更 checklist」。
