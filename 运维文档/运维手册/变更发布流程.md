# 变更发布流程

## 1. 变更分级

| 级别 | 定义 | 审批 | 窗口 |
|------|------|------|------|
| 标准 | 配置微调、非核心服务 | Team Lead | 工作日 10:00–17:00 |
| 重大 | 核心链路、数据库结构 | SRE + 业务负责人 | 周二/四 22:00–24:00 |
| 紧急 | 安全漏洞、P0 止血 | 值班经理口头 + 事后补单 | 不限 |

## 2. 发布前检查

1. 变更方案已评审（含回滚步骤）
2. 监控与告警已配置
3. 灰度策略明确（比例、观察指标、回滚条件）
4. 相关方已在发布群确认

## 3. 发布步骤（K8s 示例）

```bash
# 1. 更新镜像
kubectl set image deployment/order-service order=registry/order:v2.3.1 -n prod

# 2. 观察 rollout
kubectl rollout status deployment/order-service -n prod

# 3. 验证
curl -s https://api.internal/health | jq .
```

## 4. 回滚条件

满足任一即回滚：

- 错误率较基线上升 > 2%
- P99 延迟上升 > 50% 持续 5 分钟
- 出现数据不一致或核心功能不可用

## 5. 发布后

- 30 分钟内持续观察核心指标
- 24 小时内完成变更记录与复盘（如有异常）
